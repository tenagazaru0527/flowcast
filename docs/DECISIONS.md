## 2. 有効な決定

### 2-1. 構想レベル

| 決定 | 理由 | 差し戻し条件 |
|---|---|---|
| 入力は「線」のみ。発生源・目的地はシステム側 | 流動デザインに最短。点をプレイヤー入力にすると配置ゲーに寄る | — |
| 線の入力形式は (b) ノード間接続 | 因果の説明可能性を優先 | 将来 (d) 制御点簡約へ差し替え検討 |
| 実行中の線変更は禁止（一時停止のみ許可） | 観賞型の骨格を保つため | — |
| リプレイ外部共有を行う | ← これが決定論要件（整数演算化）の根拠 | 共有を諦めるなら決定論要件を緩められる |
| リプレイ方式は seed + 入力の再計算。イベント記録は事後分析UI用に別途 | — | — |
| 初回実装スコープはテーマ非依存の検証のみ | — | PoC-0 通過後 |

### 2-2. 決定論の要件

- 全数値 32bit 整数、小数は Q16.16 固定小数点
- 乗算は `((a * b) / 65536) | 0`。**`>> 16` は 32bit 切り詰めのため使用不可**
- `Math.random` / `Date.now` / `performance.now` 禁止
- `Math.sqrt` / `sin` / `cos` / `pow` 等の浮動小数点関数 禁止（`Math.imul` / `Math.abs` は可）
- 乱数は単一 seed の xorshift32 のみ
- `Map` / `Set` / `for...in` のイテレーション順に依存しない
- 場の更新はダブルバッファ方式
- 固定タイムステップ（3600ステップ）
- 平方根が必要な場合は `isqrt`（ビット単位法・厳密値）を使う

**検証手段**: `scripts/check-forbidden-apis.js`（`src/` 限定）と
`scripts/check-runtime-hashes.js`。CI で Node 20/22 マトリクス実行。

### 2-3. 指標と基準

| 決定 | 理由 |
|---|---|
| 基準2・3 の判定指標は **completionRatio**（生値の整数比） | `completionStep` は崖端指標。3%変位で10件中8件が未到達となり測定が成立しなかった |
| 基準3 は 1% / 3% / 10% の3水準。単調性 + 10%が1%の3.0倍以上 | 旧定義（10%で15%以上変化）は偽陽性。1%で13.4%、10%で15%＝ノイズ床を測っていた |
| `densityMax` は輻輳指標として使わない | 総流出予算が density 比例のため、source 密度は下流に依存しない source 平衡値である |
| 輻輳指標は `densityMaxExSource`（source + マンハッタン距離1 の計5セルを除外） | — |
| `completionAuc` は導入しない | completionRatio が平坦でなかったため、保険を使う条件が成立しなかった |
| **基準の閾値は変更しない** | 基準を通すための調整を構造的に禁じる |
| 掃引ハーネスは判定・順位付け・推奨を行わない | 自動探索が基準を通す方向に走ると、上記の禁止が機械的に破られる |

### 2-4. 実装方針

| 決定 | 理由 |
|---|---|
| `measure: true` 分岐内に限り計装を追加してよい | measure=false/true でハッシュが一致することを実測済み。「src/ を変更しない」制約はハッシュ不変を守る手段であって目的ではない |
| `maxStagnation` の定義は変更しない | 実験の途中で既存指標の意味を変えない。流量上限の効果は `fluxLimitedAmount` で見る |
| 微細最適化は実施しない | GC 4.62%、neighborIndex 0.17%。全施策を積んでも3〜4割。並列化は8〜10倍でモデルに触れない |
| engineVersion を上げたら同一コミットで `runtime-hashes.json` に記録 | 記録がなければ CI が FAIL する（Step 0.4 でゲート強化済み） |
| 1周1変更 | 原因帰属のため。clamp 修正と流量上限を同時に入れると効果を切り分けられない |

## 4. 保留中の判断

| 論点 | 現状 | いつ判断するか |
|---|---|---|
| **guide の定式化** | 線は「線に沿う向き」しか持たず「線に戻る向き」を持たない。帯から外れた材料は戻らず、正のフィードバックでビームが崩壊する | Step 4（adv:diff 再測定）の結果次第。制御不能なら Step 5 でポテンシャル場方式（線を低ポテンシャルの谷として焼き込む）を検討 |
| **基準4 の指標セット** | `completionStep` は全入力 -1、`maxStagnation` は動作点（edgeFluxMax 768以上）で全入力 0。3指標のうち2つが定数のため、パレート支配が totalCompleted の一次元比較に退化しており、モデルを直しても達成不能 | 流れが安定してから。**単独で緩めないこと** |
| **基準2 の閾値5%** | 太い雲は摂動に鈍く、細いビームは敏感。0.5.0 で 6/10 → 3/10 になったのは劣化ではなく流れが生まれた副作用。coherent な流れと手ぶれ耐性は原理的にトレードオフ | 流れの形が確定してから |
| **capacity / reverseThreshold** | capacity = 262,144 は観測 densityMax の約60倍で過大。ただし **下げるのは狭窄部を作った後**。候補（16,384 / 32,768 / 65,536）はいずれも reverseThreshold = 196,608 を下回り、逆流が原理的に発火不能になる | 狭窄部導入後。両者を同時に変更しないこと |
| **source / sink の多セル化** | source 1セルが入口の最狭点、sink 1セルが出口の最狭点。edgeFluxMax 128/256 の滞留は source 単独、512以上のピークは（0.4.0 では）右端の壁 | 流れが成立してから |
| **障害物・狭窄部の導入** | 均質場には詰まる場所が存在しない | 上記の後 |
| **既定の adv:diff 比** | 65536 : 16384（4:1）。Step 4 で掃引するが、**最良値が見つかっても既定値は変更せず、別途起票する** | Step 4 の後 |
| **テーマ** | 未確定。消防・延焼が第一候補（意味があり、失敗が悲惨になりにくい）。製品名案 Firebreak / Fireline / Containment（商標未確認） | PoC-0 通過後 |
| **尺** | 構想は5分以上、PoC基準は60〜90秒。更新Hz が未設定で 3600ステップの実時間換算ができない。**12Hz と定義すれば 5分ちょうどになるため、ギャップは実質存在しない可能性が高い** | 描画着手時 |
| **描画スタック** | PixiJS 第一候補（未検証）。`debug/` の可視化は Canvas 2D で、製品用スタックの既成事実にはしない | PoC-0 通過後 |
| **recycle-factory MS3 の再開** | 当初の再開条件「PoC-0 の4項目の判定が出た時点」は既に充足済み。Issue で A/B/C の選択待ち | 未処理 |

## 5. 重要な観測データ（再測定不要）

### 5-1. 0.5.0 のビームプロファイル（直進入力・既定 edgeFluxMax）

| x | 4 | 8 | 12 | 16 | 20 | 24 | 28 | 32 | 40〜56 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| σ | 0.20 | 0.35 | 0.45 | 0.60 | 2.83 | 4.87 | 6.58 | 7.45 | ≒8.0 |

x=16 まで幅1セル、x=20 で急激に崩壊、以降飽和。
**段階的でなく閾値的**であることが、正のフィードバックの証拠。

### 5-2. 0.4.0 と 0.5.0 の分布の違い

| | 0.4.0（反射壁） | 0.5.0（吸収境界） |
|---|---:|---:|
| 直進 σ（x=4） | 17.8 | 0.20 |
| 非ゼロセル数（直進） | 4,095 | 2,656 |
| 分散と直進の差（相対） | 37% | 84% |
| 迂回と直進の差（相対） | 45% | 157% |

### 5-3. source の流出律速（0.4.0 / 0.5.0 共通）

`injectionPerStep` = 1,024 に対し、source の実効流出は
`4 × edgeFluxMax` で頭打ちになる。

| edgeFluxMax | 実効流出/step | 判定 |
|---:|---:|---|
| 128 | 510.99 | 注入を捌けない |
| 256 | 1,019.9 | ほぼ同水準（実質不足） |
| 512以上 | 1,038〜1,272 | 律速しない |

**128/256 で観測される滞留・逆流・capacity クランプは、すべて
source セル単独の現象であり、経路の詰まりではない。**
